# The case against Pixie

## "No underwriter approved these rules"

Correct. The commercial bands and thresholds are an interpretation of sample data, and the renter price is illustrative. The claim is that the decision is inspectable. A carrier would replace the guideline, validate it on its book, and approve the resulting workflow.

## "The backtest is too small"

Correct. Twenty-seven bound property policies cannot establish production accuracy. Pixie keeps the sample size and named misses on screen. The next useful study is a prospective comparison of underwriters using Pixie with underwriters using their normal workflow.

## "Six agents may be theatre"

The scorer already computes the interval. The agents are useful only if their investigation and challenge improve a human decision. Pixie records each tool call, cost, and result so this can be tested. The needed ablation against one prompt and no agents has not been run.

## "The system sends every interesting case to a human"

That is deliberate. A questionable acceptance costs more than a referral. Pixie tries to make the referral cheaper by naming the unresolved fact, showing the score range, retrieving precedent, and recording the counterargument.

## "This is a collection of sponsor integrations"

Each remaining provider has a user-facing job. Federato supplies the submission and source data. Elastic answers precedent and concentration questions. Sentry records the decision and number guardrail. Expo delivers the renter workflow. The product still works when optional providers are unavailable because each fallback is explicit and labelled.

## What would falsify the product

If an underwriter reaches the same decision in the same time and with the same confidence without Pixie, the desk adds no value. The hackathon build has not run that study.
